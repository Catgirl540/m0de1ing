## 2. Token 节流纪律（硬性，违反即返工）

本工作区曾出现长会话通读大文档、重复搜索、重复读取导致的空转。以下条款对齐
高星开源 skill 的"渐进式加载 / 检索硬上限"模式（见 `01_资料库/` 索引）。

### 2.1 分层装载（渐进式）

- **L0 必读**：本文件 + README 目录导航节；
- **L1 任务级**：当前角色卡 + 对应模板，一次只装一张；
- **L2 按需**：其余文档仅在确需时读**目标片段**。禁止开局通读全部文档。

### 2.2 读取与检索预算

| 动作 | 上限 |
|---|---|
| >300 行的文件 | grep 定位后只读片段，禁止全读 |
| PDF / xlsx / pptx | 禁止直接读取，先脚本提取（文本/列名/大纲）再读产物 |
| 网络搜索（单一问题） | ≤2 轮；`01_资料库/` 索引能解答的不上外网 |
| 文献深读 | ≤5 篇即停（对标 Lupynow 硬上限） |
| 同一命令原样重试 | ≤2 次，仍失败必须换策略并报告用户 |

### 2.3 空转熔断

- 连续 2 次动作没有产生新信息（重复读同一文件、重复搜同一问题、重复跑同一命令）
  → 立即停下换策略或向用户求助；
- 输出节流：过程简述、成品一次交付；写作类任务按整节/整章交付，禁止逐段往返。

### 2.4 会话收尾（30 秒）

把本次"验证有效的经验"≤5 行追加进 `90_复盘/经验库.md`，防止下个会话重复探索。

## 3. 图表铁律（生成或修改任何图前必读）

1. 必须基于 `tools/fig_style.py`：`from fig_style import apply_style, save_fig` 并调用
   `apply_style()`。禁止 matplotlib 默认样式出图。
2. 优先复用 `tools/make_chart.py` 的 **18 种图型**（line/bar/stackarea/dualaxis/errbar/
   waterfall/pareto/hist/box/violin/scatter/bubble/heat/radar/contour/sensitivity/panel/stream），
   从表达目标选图：趋势→line/stackarea，对比→bar/waterfall/pareto，分布→hist/box/violin，
   相关→scatter/heat/bubble，机理→stream/contour，综合→panel/radar；
   流程图用 `tools/make_flowchart.py`；只有没有现成图型时才写临时脚本
   （更多科研图型见 `01_资料库/高星开源项目索引.md` 图表类）。
3. 导出一律 PNG（300dpi）+ PDF 双格式（`save_fig` 自动完成）；中文图表字号不小于 9.5pt。
4. 产出位置：正式图 → `projects/<赛题>/04_图表/figs/`；试验图 → `tools/output/`。
5. 画完执行 WORKFLOW.md 的「审图十查」，并把图登记进 `figure_index.csv`。
6. 登记后运行 `python tools/check_figures.py projects/<赛题>` 做「文-图-册」一致性
   自动检查，退出码非 0 时必须修复后才能进入下一场景。

## 4. 数据约定（编程手 → 论文手交接物）

- 一律 UTF-8 CSV、首行表头、文件名 = 图表需求单中的图号。
- 论文中出现的每一个数字必须能回溯到某个 CSV 或代码输出。**AI 禁止编造数值**；
  素材缺数时在稿中留 `【待填：数据来源】` 占位，不得虚构。

**求解类任务（MILP/模拟）三条铁律（2024C 实战教训固化）**

1. **目标符号先验证、解要独立复算**：`scipy.optimize.milp` 是最小化器，传最大化目标会把
   σ 压零、把成本当"负成本"狂种——输出还标着 Optimal。求解完成后必须用解**独立重算**
   目标值并比对，不一致 = 目标函数写错，禁止采信求解器输出。
2. **历史期显式排除**：带历史状态的规划（如上年种植），历史季槽一律不得建决策变量，
   空槽（休耕）也要显式排除，否则优化器会"回去补种"。
3. **数据键归一化**：字符串键一律 strip（"生菜 "会静默丢 30 亩）；Excel 合并单元格读入
   即 ffill；参数表的口径映射（如水稻记作"单季"、智慧大棚只录一组参数）写进数据字典
   并在取值函数里显式 fallback。

## 5. 论文语言规范

- 书面客观语体；禁「我们/大家/我觉得」，用「本文/本模型/由式(2-1)可知」。
- 每个符号首次出现必须定义，并与「符号说明」表一致；公式按问题前缀编号（(1-2)）。
- 结果描述必须带具体数值（2–4 位有效数字）与对比基准（如"提升 12.3%"）。

## 6. 文件放置规范

- 每年每题一个目录：`python tools/new_project.py <名称>` 生成，勿手工散建。
- **团队协作**：建模手/编程手阶段性成果投递到 `协作接口/`（命名与规范见其 README），
  论文手验收后归档进 `projects/<赛题>/` 对应目录并出回执。
- **论文整卷装配**：正文+图表+附录代码由项目内 `03_代码/build_paper.py` 一键装配进
  Word 模板，产出 `05_论文/论文初稿_完整版.docx`；人工只做判断句润色与 AI 声明复核。
- `00_标准/`（标准与官方模板）视为只读基线，修改须登记 `CHANGELOG.md`。
- 学习资料只进 `01_资料库/`；临时试验产物只进 `tools/output/`；
  赛后杂件一律 `99_归档/<日期>_<主题>/`，只进不改、不删除。

## 7. 自我迭代协议

1. 每项目赛后 48h 内用 `/复盘` 产出复盘，存 `projects/<赛题>/07_复盘/`；
2. 每次复盘必须产生 ≥1 条**改进落地**（改模板/改工具/改流程/改本文件），
   或写明为什么不需要；
3. 同类问题出现 ≥2 次必须固化：模板坑 → `templates/`，规则坑 → 本文件，
   工具坑 → `tools/`；
4. 结构性修改登记 `CHANGELOG.md`（一行一条）。

## 8. 红线

- 不虚构数据、文献、竞赛规则；不确定的内容标注【待确认】并提示用户核实。
- 摘要与正文数字必须互检一致后才允许定稿（质检角色卡 P0 项）。
- **AI 合规（参赛规则 2026 第 6 条）**：AI 只能辅助，参赛队对作品的原创性、
  真实性、准确性负全责；遵守官方《AI 工具使用规定》，AI 生成内容须人工重述
  改写后使用，如实说明 AI 使用情况。
- **格式硬条款不达标不许提交**：正文 ≤30 页无目录、电子版 ≤20MB 且首页 = 摘要页、
  支撑材料 ≤20MB、附录含全部可运行源代码、全稿无身份信息（逐条见
  `00_标准/交付物标准.md` §0）。
