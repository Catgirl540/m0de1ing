# 协作接口（论文手枢纽 · 建模手/编程手成果投递口）

> **角色定位**：论文手是协作枢纽。建模手、编程手把阶段性成果投递到本目录，
> 论文手验收后归档进 `projects/<赛题>/` 对应目录并出回执。
> 本目录只做**交接暂存**，不替代 projects 的产出结构（完全兼容，见"归档映射"）。

## 目录约定

| 子目录 | 谁投 | 投什么 |
|---|---|---|
| `建模手投递/` | 建模手 | 模型卡片、假设清单、方法对比表、公式推导拍照/文档 |
| `编程手投递/` | 编程手 | 结果 CSV、求解代码包、运行说明、图表数据 |
| `数据与附件/` | 任何人 | 题目原文、官方附件、补充数据（只进不改） |
| `论文手回执/` | 论文手 | 验收回执、缺件清单、口径疑问（建模/编程手在此查回复） |

## 投递命名规范

```
MMDD_角色_内容_v版本.扩展名
例：0911_建模手_问题二模型卡片_v2.md
    0911_编程手_Q2情景结果_v1.csv
    0912_编程手_求解代码包_v3.zip
```

- 版本只增不改：改内容 = 新版本号，**不覆盖他人已投文件**；
- 一天后仍需修改的，先在回执目录留言再投新版。

## 各阶段投递清单（对照 WORKFLOW.md 门禁）

| 门禁 | 建模手投 | 编程手投 |
|---|---|---|
| G2 骨架（T+2–4h） | 问题思路一页 + 方法候选表 | 环境自检截图 / 依赖清单 |
| G3–G4 求解（T+4–38h） | `模型卡片`（按 templates/模型卡片.md 填）| 结果 CSV（UTF-8、首行表头、文件名=图号）+ 代码包（含一键运行 README）|
| G5 深化（T+38–52h） | 可扰动参数清单 | 灵敏度数据 CSV |
| 全程 | 假设变更即时投递 | 数据口径变更即时投递 |

**CSV/代码规范**（与 AGENTS.md §4 一致）：CSV 首行表头、文件名=图表需求单图号；
代码附 README（环境、依赖、一键运行命令、输出位置）；随机种子固定。

## 论文手动作（收到投递后四步）

1. **总揽审查**：`/审查 <赛题>`（角色卡 09）——先 `review_crosscheck.py` 出机器底稿，
   再按三条对抗线深查：是否正确理解题意、建模与代码是否一致、优化空间、创新点与效果度量；
   产出《审查意见单》投回执目录，**P0 未清零的成果不进论文**；
2. **验收**：对照 `00_标准/交付物标准.md`（数字可溯源？口径写了吗？能重跑吗？）；
3. **归档**：模型卡片 → `projects/<赛题>/02_建模/`；结果 CSV → `03_代码/`；代码包 → `03_代码/`；
   官方文件 → `01_审题/`；
4. **回执**：在 `论文手回执/` 写 `MMDD_回执_内容.md`——收了什么、缺什么、口径疑问，
   @对应角色。

## 红线

- 投递物任何位置不得出现队号/姓名/学校（提交硬条款，从源头遵守）；
- 数据口径变更必须回执确认后才允许进论文；
- AI 会话处理本目录投递物时同样受 `AGENTS.md` 约束（token 纪律、不编造数值）。
